I found 12 concrete issues. The most serious is the insecure predictable cache fallback; the most common correctness failures will come from lossy argv parsing and tab/newline-delimited records.

The included tests reached 34 passes, but the live collector test could not run in this read-only environment because `mktemp` could not write to `/tmp`. That failure itself exposed one robustness issue below.

## Findings

1. **High — insecure predictable cache under `/tmp`**

   [larry_sessions.sh](larry_sessions.sh:24), lines 24, 28, 97–112, 218–256

   When `XDG_RUNTIME_DIR` is absent, the script uses the shared, predictable `/tmp/larry.status`. `mkdir -p` does not verify ownership, permissions, or symlinks. Another local user can pre-create cache paths or symlinks such as `names/<pid-start>`, `<hash>.lock`, or `<hash>.tmp`. Subsequent redirections may overwrite files writable by the bar user. Default permissions can also expose cached transcript prompts to other users.

   Minimal fix: require a valid user-owned `XDG_RUNTIME_DIR`, or create a private fallback with `mktemp -d` and mode `0700`. Verify the cache is a real directory owned by `UID`, set `umask 077`, and create files atomically without following attacker-created paths.

2. **Medium — untrusted data breaks the TSV output protocol**

   [larry_sessions.sh](larry_sessions.sh:220), lines 220–256 and 262–276

   Cached fields and final rows are separated with tabs/newlines, but several inputs are not fully sanitized:

   - OpenCode titles
   - hook-provided names
   - LLM titles
   - cwd/project names
   - Hyprland titles containing newlines
   - cache file contents

   A tab shifts JSON fields; a newline creates a fake additional session row. This can cause malformed/wrong records, bogus PIDs, incorrect attachment state, or total collector failure. `Text.PlainText` protects QML rendering, but not this intermediate parser.

   Minimal fix: do not serialize through TSV. Build each record with `jq -n --arg ...`, or use NUL-delimited fields and a parser that preserves boundaries. Likewise, store the per-process cache as JSON.

3. **Medium — process filtering loses argv boundaries**

   [larry_sessions.sh](larry_sessions.sh:52), lines 52–58, 180–197, 206

   `ps ... args` and `/proc/.../cmdline | tr '\0' ' '` collapse the real argv array into text. `awk '{print $2}'` consequently cannot distinguish a subcommand/flag from a positional prompt. Examples such as a prompt whose first word is `exec`, or any prompt containing the token `mcp-server`, `-p`, or `--print`, are excluded even if interactive. Quotes in the original command line cannot recover the lost boundaries.

   Minimal fix: read `/proc/$pid/cmdline` as NUL-delimited arguments (`mapfile -d ''`) and apply agent-specific filtering to actual argument positions.

4. **Medium — async title locking is non-atomic**

   [larry_sessions.sh](larry_sessions.sh:100), lines 100–113

   Checking `-e "$f.lock"` and then truncating it is a TOCTOU race. Two collector instances can both pass the check and launch Ollama requests. This is realistic because Omarchy may instantiate the widget twice, and separate shell/plugin instances can poll simultaneously. Both writers also share `$f.tmp`, so one can move or overwrite the other’s temporary file.

   Minimal fix: acquire an atomic lock with `mkdir "$f.lock"` or `flock`, and give each writer a unique `mktemp` file before an atomic `mv`.

5. **Medium — cache files are trusted without validation**

   [larry_sessions.sh](larry_sessions.sh:220), lines 220–222, 254–263

   Any nonempty per-process cache is accepted. Corruption, a partial write, or malicious cache contents can inject arbitrary `src`, SID, name, prompt, and especially `kpid`. The latter is passed to `jq --argjson`, so a nonnumeric value makes window lookup fail. Invalid `src` also violates the advertised output contract.

   Minimal fix: store cache entries as JSON, write them atomically, and validate types/ranges/enums before use. Delete and rebuild invalid entries.

6. **Medium — simultaneous sessions can be assigned the wrong transcript**

   [larry_sessions.sh](larry_sessions.sh:129), lines 129–150

   Claude and Codex transcript matching accepts the first file within a broad ±20-second window. `codex_first_prompt` ignores its `cwd` argument entirely. Two sessions launched close together can therefore receive the same transcript and title; ordering by modification time does not establish process ownership.

   Minimal fix: use a session identifier from argv/environment when available. Otherwise choose the closest timestamp, include cwd/project metadata in matching, and prevent one transcript from being assigned to multiple live processes during a poll.

7. **Medium — PID-exit/reuse races can cache data for the wrong process**

   [larry_sessions.sh](larry_sessions.sh:203), lines 203–230

   The PID is checked once, then `/proc/$pid` is read repeatedly. If the process exits and its PID is reused, argv, start time, cwd, ancestry, and agent classification may come from different processes. If `start_epoch` fails, it returns `0`; the collector continues with a `pid-0` cache key and a huge age rather than dropping the row.

   Minimal fix: read and validate `/proc/$pid/stat` start ticks before and after gathering data, require a positive start time, and discard the row if the start ticks changed or any essential read failed.

8. **Medium — `mktemp` and cache setup failures are ignored**

   [larry_sessions.sh](larry_sessions.sh:28), lines 28, 178–201

   `mkdir -p` and both `mktemp` calls are unchecked. When the runtime directory is missing, full, unwritable, or read-only, the script continues with empty filenames, attempts to write `.pids`, and finally invokes `jq` with an empty path. Because it runs every eight seconds, this can generate recurring errors while the UI silently replaces sessions with `[]`.

   This occurred during review.

   Minimal fix: check every setup operation and exit with a deliberate `[]` or last-known result. For example, `cands=$(mktemp ...) || { printf '[]\n'; exit 0; }`.

9. **Medium — focus command embeds an unvalidated address into Lua**

   [BarWidget.qml](BarWidget.qml:140), lines 140–145

   `s.address` is concatenated into a Lua program. Today it normally originates from Hyprland and looks like `0x...`, but the collector/cache pipeline is not trustworthy enough to assume that invariant. Crafted or corrupted JSON returned over IPC could break out of the string and alter the dispatched Lua expression.

   Minimal fix: reject anything not matching `^0x[0-9a-fA-F]+$` before constructing the command. Prefer a Hyprland API that accepts the address as a distinct argument if available.

10. **Low — collector failures are presented as “no agents”**

    [BarWidget.qml](BarWidget.qml:127), lines 127–133

    Any malformed output, missing dependency, permission failure, or collector crash sets `sessions=[]`. The face then reports that Larry is asleep, indistinguishable from a successful empty scan. Exit status and stderr are ignored.

    Minimal fix: retain the last valid session list and expose a `sessionsHealthy`/error state. Clear the list only after a successful parse of a successfully exited collector.

11. **Low — missing heartbeat is displayed as three confirmed outages**

    [Panel.qml](Panel.qml:129), lines 129–150 and 202–226

    On missing or malformed heartbeat data, all service booleans become false. The panel then renders Ollama, Qdrant, and backup as red `DOWN`, while the bar intentionally treats the same condition as unknown/dimmed. This produces false outage reports after boot, during an atomic rewrite, or on parse failure.

    Minimal fix: add `haveStatus` to the panel and render `UNKNOWN` in a neutral color until valid heartbeat data has been loaded.

12. **Low — unbounded external counts can create excessive QML objects**

    [Panel.qml](Panel.qml:129), lines 129–140 and 483–503

    `fleet.total`, `fleet.online`, and `fleet.down` are accepted without type or range checks. `Repeater.model: fleetTotal` can instantiate an arbitrarily large number of rectangles if the heartbeat file is malformed or compromised. Dot status is also calculated from `fleetTotal - fleetDown.length` instead of the supplied `fleetOnline`, so inconsistent data is displayed incorrectly.

    Minimal fix: require finite nonnegative integers, clamp totals to a modest maximum, validate `down` as an array, and base the visualization on the validated `fleetOnline`.

## Other concrete edge cases

- **Low:** [larry_sessions.sh](larry_sessions.sh:133), lines 133 and 142 use `for f in $(ls ...)`; whitespace or glob characters in generated paths are word-split. Use arrays/globs plus `mapfile`, or `find -print0`.
- **Low:** [larry_sessions.sh](larry_sessions.sh:84), lines 84–91 only deduplicate helpers within four ancestors. Agents behind five or more wrappers can appear twice. Walk to PID 1 with a cycle/depth guard.
- **Low:** [larry_sessions.sh](larry_sessions.sh:94), lines 94–113 never prune `names` or `llm`; long uptimes with many sessions cause unbounded cache growth. Prune entries older than a defined TTL.
- **Low:** [README.md](README.md:17) says stale heartbeat triggers an alert, contradicting the implementation and changelog, which deliberately dim it. Update the trigger description.
- **Low:** [BarWidget.qml](BarWidget.qml:24), lines 24–25 converts a file URL by stripping `file://`; percent-encoded paths remain encoded, so installation under a path containing spaces or non-ASCII characters can fail. Use a proper local-file URL conversion facility.

## Ranked top five

1. Predictable, symlinkable, potentially world-readable `/tmp` cache.
2. TSV/newline framing allows untrusted titles, paths, and cached text to corrupt session records.
3. Lossy argv parsing misclassifies interactive processes and cannot safely reason about untrusted arguments.
4. Non-atomic LLM locking/temp-file handling causes duplicate work and races across widget instances.
5. Timestamp-only transcript matching assigns wrong prompts/titles to concurrently started sessions.
